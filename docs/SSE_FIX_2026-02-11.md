# SSE 400 Error Fix - 2026-02-11

## Problem

SSE (Server-Sent Events) endpoint was returning `400 Bad Request` with error:
```
GET http://localhost:8000/api/events/stream?ticket=... 400 (Bad Request)
```

Frontend useSSE hook was stuck in reconnection loop:
```
[SSE] Connection lost. Reconnecting in 4s
```

## Root Causes

### Issue 1: group_ids Overwritten in Ticket Auth Flow

**File:** `backend/app/routes/events.py`
**Lines:** 96-125

**Problem:**
```python
if ticket:
    # Line 100: Extract group_ids from ticket ✅
    user_id_str, group_ids, expires_at = ticket_data
    # ...
# Line 123: BUG - Overwrites group_ids with empty list! ❌
group_ids = [g.strip() for g in groups.split(",") if g.strip()]
if not group_ids:
    raise HTTPException(status_code=400, detail="No groups specified")
```

**Why it failed:**
1. Frontend sends `?ticket=XXX` (no `groups` parameter when using ticket)
2. Backend extracts `group_ids` from ticket correctly
3. Code then overwrites `group_ids` by parsing empty `groups` query param → `[]`
4. Validation fails: "No groups specified" → 400 error

**Fix:**
- Only parse `groups` query param when using legacy token auth
- For ticket auth, use `group_ids` already extracted from ticket

```python
if ticket:
    # Extract from ticket
    user_id_str, group_ids, expires_at = ticket_data
    user_id = user_id_str
    # group_ids already set — no need to parse query param ✅
elif token:
    # Parse from query param for legacy auth
    group_ids = [g.strip() for g in groups.split(",") if g.strip()]

# Validate
if not group_ids:
    raise HTTPException(status_code=400, detail="No groups specified")
```

### Issue 2: Missing Query() Annotation in Ticket Endpoint

**File:** `backend/app/routes/events.py`
**Line:** 51

**Problem:**
```python
@router.post("/events/ticket")
async def create_sse_ticket(
    request: Request,
    groups: str,  # ❌ No Query() annotation
    credentials: HTTPAuthorizationCredentials = Security(_security),
):
```

**Why it failed:**
- Frontend sends: `POST /events/ticket?groups=123,456` (query parameter)
- FastAPI without `Query()` annotation tries to parse from request **body** for POST
- Mismatch → validation error or missing parameter

**Fix:**
```python
from fastapi import Query

@router.post("/events/ticket")
async def create_sse_ticket(
    request: Request,
    groups: str = Query(..., description="Comma-separated group IDs"),  # ✅
    credentials: HTTPAuthorizationCredentials = Security(_security),
):
```

## Architecture Notes

### SSE Authentication Flow (Ticket-Based)

```
┌─────────────────────────────────────────────────────┐
│  Frontend (useSSE hook)                             │
└─────────────────────────────────────────────────────┘
         │
         │ 1. POST /api/events/ticket?groups=123,456
         │    Authorization: Bearer JWT
         ↓
┌─────────────────────────────────────────────────────┐
│  Backend: create_sse_ticket()                       │
│  - Validate JWT (decode_token)                      │
│  - Extract user_id from JWT                         │
│  - Parse groups from query param                    │
│  - Generate ticket: (user_id, groups, expires_at)  │
│  - Return: {ticket: "XXX", expires_in: 60}          │
└─────────────────────────────────────────────────────┘
         │
         │ 2. GET /api/events/stream?ticket=XXX
         │    (EventSource connection, no JWT in URL)
         ↓
┌─────────────────────────────────────────────────────┐
│  Backend: event_stream()                            │
│  - Pop ticket from _SSE_TICKETS                     │
│  - Extract (user_id, groups, expires_at)            │
│  - Validate not expired                             │
│  - Authorize groups (public or user_groups check)   │
│  - Subscribe to SSE queue                           │
│  - Stream events forever (or max 2 hours)           │
└─────────────────────────────────────────────────────┘
```

### Why Ticket-Based Auth?

**Security Benefits:**
- ✅ JWT never appears in EventSource URL (URL is logged, cached, appears in history)
- ✅ Ticket is single-use (consumed on first connection)
- ✅ Ticket is short-lived (60s TTL)
- ✅ JWT exposure limited to HTTPS POST body (not GET query params)

**Legacy Token Auth:**
- Still supported for backward compatibility
- Uses `?token=JWT&groups=123,456` in URL
- Less secure (JWT exposed in logs/history)
- Will be deprecated in future

## Lessons Learned

1. **Don't reuse variable names across auth branches** — ticket auth sets `group_ids`, token auth sets `group_ids`, then shared code overwrites it → bug
2. **FastAPI param parsing is strict** — POST endpoints need `Query()` for query params, otherwise parsed from body
3. **Test both auth paths** — ticket auth worked in isolation, token auth worked in isolation, but shared validation code broke ticket auth
4. **Watch for variable shadowing** — Same variable name assigned in multiple branches makes bugs hard to spot
